# 앨범아트

- 관리자 곡 생성/수정 화면에서 선택적으로 업로드합니다. JPG/PNG/WebP 정지 이미지, 최대 3MB입니다.
- 서버는 파일을 직접 디코딩하여 검사하고, 최대 4천만 픽셀까지 허용합니다. 비율을 유지하고 자르지 않으며 최대 1000px WebP로 저장합니다. 작은 이미지는 확대하지 않습니다.
- `musics.album_art_key`는 `albumart/{musicId}/{고유값}.webp`를 참조합니다. 공개 표시는 `/api/content/albumart/{musicId}/{file}`을 이용합니다.
- R2 키가 없는 기존 곡은 로컬 WebP, 이미지 로딩 실패 시 `empty.svg`를 표시합니다. `empty.svg`는 로컬에 유지합니다.
- 곡 저장과 이미지 업로드는 분리되어 있습니다. 이미지 업로드 실패 후 저장을 재시도해도 이미 생성한 곡 ID를 사용합니다. 화면을 나갔거나 새로고침했다면 생성된 곡을 선택하여 이미지만 다시 업로드합니다.
- 교체는 새 R2 파일 업로드 → 이전 키가 변하지 않았는지 확인하며 DB 연결 → 이전 파일 정리 순서입니다. 동시 교체 시 충돌한 요청은 실패로 표시합니다. 정리 실패는 서버 로그에 키를 남기고 정상 저장은 유지합니다.
- 관리자 세션만 업로드할 수 있으며 viewer는 조회만 가능합니다. R2 연결은 서버에만 존재하고 버킷 공개 설정은 필요하지 않습니다.

## 환경 설정

기존 R2 설정을 사용합니다. 해당 버킷에 Object Read & Write 권한이 필요합니다. 로컬과 배포 환경 모두 같은 권한을 설정해야 합니다. 비밀 값은 저장소나 문서에 기록하지 않습니다.

## DB 및 기존 이미지 이전

```sh
node scripts/albumArtMigration.mjs          # 조회, 백업, 사전 검증
node scripts/albumArtMigration.mjs --schema # 앨범아트 열과 마이그레이션 이력 추가
node scripts/albumArtMigration.mjs --apply  # 기존 WebP 업로드 및 DB 연결
```

실행마다 `.backups/album-art-*/before.json`과 `report.json`을 남깁니다. 로컬 WebP는 삭제하지 않습니다. 이전은 원본 바이트를 그대로 업로드하고 다시 내려받아 SHA-256을 비교한 뒤 DB에 연결합니다. 이미 연결된 곡은 덮어쓰지 않고 읽기 검증만 합니다. 새 파일 키는 원본 해시로 결정되어 재실행할 수 있습니다.

공개 목록은 캐시됩니다. 최초 이전 후 새 코드 배포/개발 서버 재시작으로 새 목록을 확인합니다. 이전 전 캐시가 남더라도 기존 로컬 이미지는 계속 표시됩니다. 관리자에서 이미지 업로드/교체 시에는 공개 목록 캐시를 즉시 무효화합니다.

## 검증

```sh
node --import tsx --test scripts/albumArt.test.ts
ALBUM_ART_TEST_URL=http://localhost:3001 node scripts/checkAlbumArtApi.mjs

npx tsc --noEmit
```

API 검증은 로컬 개발 서버와 관리자 세션 설정이 필요하며, 곡 데이터나 R2 파일을 생성하지 않습니다. 정상 업로드·교체·실패 후 재시도는 R2 쓰기 권한이 준비된 뒤 별도로 확인합니다.

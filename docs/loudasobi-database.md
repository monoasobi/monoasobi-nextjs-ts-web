# loudasobi 공용 DB 기반

## 최신 변경: 공유 가사 직접 조회 (2026-09-24)

이 절이 아래 최초 구축 기록보다 우선합니다. 0005_shared_lyrics를 운영에 적용했습니다.
- loudasobi는 MONOASOBI `lyric_tracks`를 직접 읽습니다. 가사 복사·가사 편집 기능은 제공하지 않습니다.
- `loudasobi_music_settings.sync_offset`(초, 기본 0)을 추가했습니다. 최종 sync = 공통 트랙 sync + 전용 sync_offset입니다. 양수는 가사를 늦게 표시합니다.
- 콜 테이블 FK는 사본 트랙이 아닌 `musics.id`를 참조합니다. 공통 트랙 삭제 시에도 콜 문서는 보존되며, 콜 편집 단계에서 연결 유효성을 확인해야 합니다.
- `loudasobi_lyric_tracks`는 보관용으로 남겼고 서비스에서 읽거나 쓰지 않습니다. 기존 원문·설정·콜 문서가 보존되었고 외래 키 검사도 통과했습니다.
- 이번 적용 직전 백업: `.backups/loudasobi-foundation-1790258678471.json`.

### 다음 배포 및 ID 보강

MONOASOBI 줄 ID 보존/생성 코드가 준비되어 있습니다. **이 코드를 배포하고 열려 있는 가사 편집기를 새로고침한 뒤** 아래 ID 보강을 실행합니다. 기존 운영 저장기는 ID를 제거하므로 아직 운영 ID 보강은 하지 않았습니다.

```sh
node --env-file=.env scripts/backfillLyricIds.mjs
node --env-file=.env scripts/backfillLyricIds.mjs --apply --confirm-mono-deployed
```

원문·시간·sync는 수정하지 않고 누락된 ID만 추가합니다. 실행 직전 가사 백업을 남기며 같은 작업을 반복해도 기존 ID를 교체하지 않습니다. 이후 일반 수정은 ID를 유지하고 타임라인 줄 분할은 새 줄에만 새 ID를 부여합니다. JSON 전체 교체 시 ID를 제거하면 새 줄로 취급됩니다.

ID 보강 전에도 가사 조회와 싱크 조정은 가능합니다. 실제 콜 연결은 ID 보강 후 구현합니다. 부분 떼창은 lineId와 선택 원문을 함께 저장하고 원문 변경/줄 삭제 시 재확인 대상으로 처리해야 합니다. 이 유효성 UI는 아직 구현 전입니다.

향후 스키마만 적용할 때는 `scripts/loudasobiFoundation.mjs --schema-only`로 사전 검증하고 승인 후 `--schema-only --apply`를 사용합니다. 과거 가사 복사 모드는 다시 사용하지 않습니다.

## 현재 상태

- 스키마와 마이그레이션, MONOASOBI 논리 삭제 코드를 준비했습니다.
- 운영 DB를 읽어 백업하고 로컬 복제본에서 마이그레이션과 가사 이관을 검증했습니다.
- 2026-09-24 운영 DB에 `deleted_at` 및 전용 테이블 3개를 적용했습니다. MONOASOBI 서비스 배포는 사용자 진행 대기 중입니다. 배포 완료 전까지 관리자 쓰기를 중단합니다.
- 기존 곡 35개와 원본 데이터를 보존했으며, 가사 35곡·1,999줄의 내용과 타이밍이 동일하게 복사되었음을 확인했습니다. 전용 설정은 모두 비공개, YouTube ID는 빈 값(NULL), 콜 가이드는 빈 문서입니다. 외래 키 검사도 통과했습니다.
- 적용 직전 백업: `.backups/loudasobi-foundation-1790223315679.json` (로컬 복제본은 같은 경로에 `.sqlite`가 붙습니다).
- loudasobi 앱의 DB 연결 및 관리자 화면은 후속 작업입니다. 현재 정적 화면은 그대로 유지합니다.

## 테이블과 책임

| 테이블 | 역할 |
| --- | --- |
| `musics` | 양쪽 서비스의 공통 곡 및 일어·한글·영어 제목. `deleted_at IS NULL`만 활성 곡입니다. |
| `loudasobi_music_settings` | `music_id`당 한 행. 전용 `youtube_id`, 영문 색상 이름 `fan_light_color`, `publish`를 저장합니다. |
| `loudasobi_lyric_tracks` | `music_id`당 한 트랙. `sync`와 다국어 가사 JSON을 저장합니다. |
| `loudasobi_call_guides` | loudasobi 가사 트랙당 한 문서. 최초 값은 `{ "cues": [] }`입니다. 상세 큐 스키마는 관리자 구현 단계에서 확정합니다. |

스키마 변경과 마이그레이션은 이 저장소에서만 관리합니다. loudasobi에서 같은 DB에 별도의 마이그레이션 이력을 만들거나 `push`하지 않습니다.

`publish` 기본값은 false이며 설정 행이 없는 곡도 비공개로 취급합니다. 공개에는 전용 YouTube ID가 필요합니다. MONOASOBI의 MV ID를 대신 사용하지 않습니다. 팬라이트 hex 값은 loudasobi 로컬 색상 사전에서 관리합니다.

MONOASOBI 신규 곡은 loudasobi 관리자에서 활성 `musics`를 기준으로 설정을 LEFT JOIN하여 자동 노출합니다. 공개 목록은 `deleted_at IS NULL AND publish = true`로 제한합니다. 신규 가사의 자동 복제는 하지 않고 관리자가 명시적으로 가져온 뒤 해당 음원에 맞게 조정합니다.

## 가사 이관

운영 `lyric_tracks`를 최초 한 번 복사합니다. 원문·다국어 필드·시작/끝 시간·sync는 보존하며 가사 줄에 안정적인 문자열 `id`만 추가합니다. 가사는 분절하지 않습니다. 부분 떼창은 이후 이 ID와 문자열 선택 범위로 연결합니다.

스크립트 재실행은 기존 loudasobi 문서를 덮어쓰지 않습니다. 원본 가사 변경을 지속 동기화하는 도구가 아닙니다. 가사가 있는 곡에는 비공개 설정과 빈 콜 가이드도 생성합니다. 모든 시간은 기존 초 단위를 유지하며, 새 음원과의 일치는 별도 확인해야 합니다.

## 삭제와 복구

MONOASOBI 곡 삭제는 `deleted_at`과 `updated_at`만 갱신합니다. 소설·만화·가사·콜·설정·R2 파일을 삭제하지 않습니다. 관련 공개 조회 및 콘텐츠 API에서도 삭제된 곡을 제외합니다. 외래 키는 연쇄 삭제하지 않습니다.

`restoreMusic` 서버 함수는 준비되어 있지만 복구 UI/API는 아직 없습니다. 향후 복구 진입점에는 관리자 인증과 공개 캐시 무효화가 필요합니다. 복구하면 기존 loudasobi `publish` 값도 유지되므로 이전에 공개했던 곡은 다시 공개 대상이 됩니다.

## 운영 적용 순서 — 관리자 쓰기 일시 중단 필요

운영 중인 이전 MONOASOBI 삭제 코드는 관련 행을 먼저 실제 삭제합니다. 새 외래 키만 추가하면 마지막 곡 삭제가 실패하더라도 앞서 지운 가사는 복구되지 않습니다. 따라서 배포 전까지 기존 삭제 기능을 사용하면 안 됩니다.

1. 사용자와 적용 시간을 정하고 MONOASOBI 관리자 쓰기(별도 API 호출 포함)를 일시 중단합니다.
2. 이 저장소 루트에서 아래 명령으로 최신 백업, 로컬 사전 검증, 운영 마이그레이션 및 이관을 수행합니다.
3. 즉시 새 MONOASOBI 코드를 배포합니다. 새 코드가 배포되기 전에는 관리자 쓰기를 재개하지 않습니다.
4. 배포 성공을 확인한 뒤 관리자 쓰기를 재개합니다. 이후 loudasobi에 동일 DB 연결 및 공개/관리자 조회를 연결합니다.

```sh
# 원격 읽기만 수행: 백업 및 로컬 복제본 검증
node --env-file=.env scripts/loudasobiFoundation.mjs

# 위 일시 중단과 배포 준비가 확인된 경우에만 운영에 적용
node --env-file=.env scripts/loudasobiFoundation.mjs --apply --confirm-delete-paused
```

백업은 Git에서 제외된 `.backups/`에 저장합니다. 전체 데이터가 들어 있으므로 외부에 공유하지 않습니다. 백업 생성과 로컬/운영 원본 행 보존 확인이 포함되어 있습니다. 마이그레이션과 이관은 별도 단계이므로 이관 실패 시 테이블은 이미 생성되었을 수 있습니다. 원인을 해결한 후 동일 명령을 재실행하며 테이블을 삭제해 되돌리지 않습니다. 이전 파괴적 삭제 코드로 되돌리는 배포도 금지합니다.

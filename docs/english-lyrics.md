# loudasobi 영문 가사 작업

- 대상: 활성 35곡, 1,999줄. 2026-09-27 조회 시 `en`·`enReading` 작성분은 모두 0줄입니다.
- `en`: 일본어 원곡 의미를 전달하는 영어 번역. 공식 영어판의 개사 가사로 대체하지 않습니다.
- `enReading`: 일본어 원곡을 따라 부르기 위한 로마자 독음. 영어 번역문의 발음 표기가 아닙니다.
- 원문, 한국어 번역·독음, 줄 ID, 줄별 타이밍, 트랙 sync는 변경하지 않습니다. 기존 영문 값이 있으면 덮어쓰지 않습니다.

## MONOASOBI 표시·저장 원칙

- 공개 가사 조회, 관리자 목록·JSON 편집, 타임라인 조회에서는 `en`·`enReading`을 제외합니다. 데이터 자체는 공유 DB의 `lyric_json`에 남겨 loudasobi가 직접 조회합니다.
- MONOASOBI 저장 시 트랜잭션 안에서 현재 DB 행을 읽고, 같은 줄 ID의 영문 필드를 보존합니다. 클라이언트의 누락·오래된 영문 값으로 덮어쓰지 않습니다.
- 줄 삭제는 기존 동작대로 해당 줄 전체를 삭제합니다. ID를 제거·교체하거나 새로 분할한 줄에는 다른 줄의 영문 자료를 임의로 복사하지 않습니다. 기존 줄 원문을 수정했다면 영문 번역·독음도 별도 재검토가 필요합니다.
- 영문 자료 입력은 별도 데이터 작업으로 수행하며 MONOASOBI에 영문 편집 UI를 추가하지 않습니다.

## 진행 상태와 적용 순서

1. 영문 숨김·보존 코드 준비 및 정적/순수 함수 검증.
2. MONOASOBI에 배포하고 열려 있는 관리자 편집기를 새로고침합니다.
3. 35곡을 곡별로 원문 대조 → 영어 번역·로마자 독음 작성 → 줄 수·ID·원문 일치 확인 → 백업 후 빈 영문 필드만 저장합니다.
4. 적용 전후 원문·한국어 자료·타이밍·ID 보존 및 loudasobi 표시를 확인합니다.

2026-09-28 완료: 배포 확인 후 활성 **35곡·1,999줄 전체**에 `en`과 `enReading`을 운영 DB에 입력했습니다. 첫 6곡 309줄 이후 중단되었던 작업을 이어서 나머지 29곡 1,690줄을 반영했습니다.

- 전체 운영 데이터를 최초 스냅샷과 대조해 영문 외 모든 줄 필드와 트랙 sync가 동일함을 확인했습니다.
- 원래 영어로 작성된 가사·코러스는 원문 그대로 유지했습니다.
- 번역은 의미 전달용 초안입니다. 로마자 독음은 원문과 기존 한국어 독음을 참고했으며 실제 음원을 청취한 전곡 검수는 하지 않았습니다.
- MONOASOBI 조회의 영문 제거와 loudasobi 조회의 영문 포함 경로를 코드로 확인했습니다. 브라우저 화면 QA는 별도입니다.

## 작업 자료와 재확인

MONOASOBI의 `.backups/english-lyrics/`에 곡별 원본(`ID.source.json`), 작성분(`ID.english.json`), 반영 직전 백업(`ID.before-TIMESTAMP.json`), 원문 표기 관련 판단(`notes.md`)을 보관했습니다. 이 폴더는 Git에서 제외되므로 자료 보존 시 별도로 백업해야 합니다.

기존 환경 변수를 불러온 상태에서 `scripts/englishLyrics.mjs`를 실행합니다.

```sh
node --env-file=.env scripts/englishLyrics.mjs status
node --env-file=.env scripts/englishLyrics.mjs check 0
```

`apply ID`는 원문 해시·줄 수·ID·작성분 형식을 확인한 뒤 빈 영문 필드만 채웁니다. 기존 영문은 덮어쓰지 않습니다. 이미 작성된 영문을 교정하려면 변경 전 값 확인과 백업을 포함한 별도 수정 절차가 필요합니다.
